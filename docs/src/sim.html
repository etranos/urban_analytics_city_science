Spatial interaction modelling

Let’s now move to model these flows. If you remember the basic Gravity model is defined as following:

\[T_{ij} = k \displaystyle \frac{V_i^\lambda M_j^\alpha}{D_{ij}^\beta}\]

And if we take the logarithms of both sides of the equation we can transform the Gravity model to something which looks like a linear model:

\[lnT_{ij} = lnk + \lambda lnV_i + \alpha lnM_j - \beta lnD_{ij}\]

The above transformed equation can be estimated as a linear model if we assume that \(y = lnT_{ij}\), \(c = lnk\), \(x_1 = lnV_i\), \(a_1 = \lambda\) etc. Hence, we can use OLS to estimate the following:

\[lnT_{ij} = lnk + \lambda lnV_i + \alpha lnM_j - \beta lnD_{ij} + e_{ij}\]

This is what is known as the log-log transformation.

There are a number of issues with such an approach though. Most importantly, our dependent variable is not continuous, but instead a discrete, positive variable (there are no flows of -324.56 people!). Therefore we need to employ an appropriate estimator and this is what the Poisson regression does. Briefly, if we exponentiate both sides, the above equation can be written as:

\[T_{ij} = e^{lnk + \lambda lnV_i + \alpha lnM_j - \beta lnD_{ij}}\] The above is in the form of the Poisson regression. So, we are interested in modelling not the mean \(T_{ij}\) drawn from a normally distributed \(T\), but, instead, the mean \(T_{ij}\), which is the average of the all the flows (i.e. counts) between any \(i\) and \(j\). For more details about the Poisson regression have a look at Roback and Legler (2021). For this practical we will estimate the commuting flows using both OLS and Poisson regressions.

But before we get into the estimation we need to build a data frame, which includes all the necessary variables. These are the origin-destination flows \(T\) between \(i\) and \(j\), the distance \(dist\) between \(i\) and \(j\) and the characteristics \(V\) and \(M\) of origin \(i\) and destinations \(j\) that we believe push and pull individuals to commute.

Let’s try now to model these flows. We will start with a simple OLS to estimate the above specifications. Please pay attention to the small trick we did. Because there are non-materialised origin-destination pairs (i.e. with 0 flows), we added a small value (\(0.5\)) in the dependent variable. Otherwise we will receive an error as the logarithm of \(0\) is not defined.

ols.model <- lm(log(`All categories: Method of travel to work`+.5) ~
                  log(distance) + log(resident) + log(workplace),
                data = commuting.si)

Constrained spatial interaction models

The Poisson (and the OLS) model we just estimated is an unconstrained spatial interaction model. Nothing forces the predicted flows to be consistent with what we already know about the system. For example, if we sum the predicted flows for all the commuters who live in Bristol, there is no guarantee that we will get the actual number of Bristol residents who commute to another local authority.

But very often we do know these totals. The census tells us how many people live in each local authority and commute elsewhere (\(O_i\), the origin totals) and how many jobs are taken by commuters in each local authority (\(D_j\), the destination totals). What we do not know, or what we want to predict, is how these totals are distributed, i.e. who commutes where. This is what constrained spatial interaction models do (Wilson 1971). There are four types:

Type What is fixed \(\sum_j T_{ij}\) \(\sum_i T_{ij}\)
Unconstrained nothing free free
Production-constrained origin totals, \(O_i\) \(= O_i\) free
Attraction-constrained destination totals, \(D_j\) free \(= D_j\)
Doubly constrained both \(= O_i\) \(= D_j\)

In this section we will estimate the production-constrained and the doubly constrained models for the same commuting flows and compare them with the unconstrained one we estimated above. The attraction-constrained model is the mirror image of the production-constrained one and you will estimate it as a task at the end.

Production-constrained model

The production-constrained model is defined as:

\[T_{ij} = A_i \, O_i \, M_j^\alpha \, D_{ij}^{-\beta} \qquad \text{where} \qquad A_i = \frac{1}{\sum_j M_j^\alpha D_{ij}^{-\beta}}\]

Compare it with the unconstrained model. The origin characteristic \(V_i^\lambda\) has been replaced by the known origin total \(O_i\) and the new term \(A_i\) is a balancing factor, which makes sure that the predicted flows from each origin add up to \(O_i\), i.e. \(\sum_j T_{ij} = O_i\). Please note that we do not estimate \(\lambda\) any more. We still estimate \(\alpha\) and \(\beta\).

An important by-product: \(1/A_i = \sum_j M_j^\alpha D_{ij}^{-\beta}\) is the gravity-based accessibility of origin \(i\) (do you remember the accessibility indicators from the lecture?). We will come back to this below.

Estimating the production-constrained model

How do we estimate \(\alpha\) and \(\beta\) when the balancing factor \(A_i\) is part of the model? Remember that the unconstrained model is, after taking logarithms, a linear model:

\[\ln T_{ij} = \ln A_i + \ln O_i + \alpha \ln M_j - \beta \ln D_{ij}\]

Here, \(\ln A_i + \ln O_i\) is a different constant for each origin. Therefore, we can estimate the model with the Poisson regression we already know, by simply adding a dummy variable for each origin, which will absorb this term. This is why this model is also known as a Poisson model with origin fixed effects. A nice property of the Poisson regression is that, when it includes such dummies, the predicted flows of each origin add up exactly to the observed ones. In other words, the constraint is satisfied by construction.

Please note that the 0 + in the formula removes the common intercept, so that we get one dummy for each origin.

We have around \(350\) origins and more than \(100,000\) origin-destination pairs. A model matrix with a dummy variable for each origin is huge, but it is almost all zeros. The base glm() function stores all these zeros and, as a result, it is very slow for this kind of models (it can take many minutes). The function glm4() of the MatrixModels package has almost exactly the same syntax, but with the argument sparse = TRUE it stores only the non-zero values. It estimates the same model in about a second. The TOL argument is the convergence tolerance, which we make stricter than the default so that the constraints are satisfied with high precision.

prod.glm <- glm4(flow ~ 0 + i + log(workplace) + log(distance),
                 family = poisson(link = "log"), data = commuting.c,
                 sparse = TRUE, control = list(TOL = 1e-7))

Doubly constrained model

If we know both the origin and the destination totals, we can use both:

\[T_{ij} = A_i \, B_j \, O_i \, D_j \, D_{ij}^{-\beta}\]

\[A_i = \frac{1}{\sum_j B_j D_j D_{ij}^{-\beta}} \qquad B_j = \frac{1}{\sum_i A_i O_i D_{ij}^{-\beta}}\]

Now all the flows are shaped by the totals and the only parameter left to estimate is \(\beta\), the friction of distance. Note that \(A_i\) depends on \(B_j\) and vice versa. We cannot solve them directly, but we can solve them iteratively: start with \(B_j = 1\), calculate \(A_i\), use it to update \(B_j\), and so on, until they stop changing. This is known as the Furness (or iterative proportional fitting) procedure, which was the traditional way of calibrating these models.

The Poisson regression gives us the same result in one go. This time we add a dummy variable for each origin and for each destination. Then, \(\ln(A_i O_i)\) is absorbed by the origin dummies and \(\ln(B_j D_j)\) by the destination dummies, and the only coefficient left is the one of distance, i.e. \(-\beta\). As the origin dummies already play the role of a constant, R drops the dummy of the first destination, which becomes the reference category. This is not a problem, as the predicted flows are not affected.

This is a big model, with around \(700\) dummies. With the base glm() it would take a very long time, but with the sparse matrices of glm4() it is again a matter of seconds.

dbl.glm <- glm4(flow ~ 0 + i + j + log(distance),

Comparing the models

Let’s now compare the three models. For the unconstrained model we use the Poisson model we estimated earlier. We use three goodness-of-fit measures: the root mean squared error (RMSE), the \(R^2\) (here the squared correlation between observed and predicted flows) and the Sørensen index (also known as the Common Part of Commuters, CPC), which is very popular in the flow literature. It is the proportion of commuters who are correctly allocated to their origin-destination pair. It ranges between \(0\) (nothing in common) and \(1\) (perfect). For more information about the CPC, have a look at Thompson et al. (2019).

\[CPC = \frac{2\sum_{ij} \min(T_{ij}, \hat{T}_{ij})}{\sum_{ij} T_{ij} + \sum_{ij} \hat{T}_{ij}}\]

# Predictions of the unconstrained model for the same origin-destination pairs
T.unc <- predict(glm.model, newdata = commuting.c, type = "response")

# A function which takes a vector of predicted flows and returns the fit statistics
# and the largest errors in the origin and destination totals.
evaluate <- function(pred) {
  obs <- commuting.c$flow

  tibble(RMSE = sqrt(mean((obs - pred)^2)),
         R2 = cor(obs, pred)^2,
         CPC = 2 * sum(pmin(obs, pred)) / (sum(obs) + sum(pred)),
         origin.error = max(abs(tapply(pred, commuting.c$i, sum) - O)),        # largest error in origin totals
         destination.error = max(abs(tapply(pred, commuting.c$j, sum) - D)))   # largest error in destination totals
}

models <- list("Unconstrained" = T.unc,
               "Production-constrained" = fitted(prod.glm),
               "Doubly constrained" = fitted(dbl.glm))

This is not a Machine Learning introduction…

… but maybe a sneak preview of the philosophy behind modern data science approaches to answer computational problems. We are using the caret package to:

  • split our data into a training and a test data set

  • train three different models using only the training data set: a linear regression (lm), the Poisson regression (glm) we are already familiar with, and a random forest

  • use the estimated models to make out-of-sample predictions using the test data set, i.e. data that the models have never seen

  • compare the predictions with the actual flows and choose the best model.

This is obviously an oversimplification, but it provides a good preview of machine learning frameworks. The key idea is that we do not judge a model by how well it fits the data we used to estimate it, but by how well it predicts new data.

It is worth browsing the caret package.

The random forest is the only real machine learning model here. It is an ensemble of many decision trees. Each tree splits the data repeatedly using the explanatory variables (e.g. is the distance smaller than x km?) and the final prediction is the average across the trees. Unlike the regressions, we do not tell it what the relationship looks like. It can find non-linear relationships and interactions between variables on its own. We use the ranger package, which is a fast implementation of random forests, through caret. If you do not have it, run install.packages("ranger").

First, we split the data. We keep \(80\%\) of the observations for training and \(20\%\) for testing. Please note that we do not change commuting.si. Instead, we create a new data frame without missing values and with a shorter name for the number of commuters. The set.seed() makes the random split reproducible.

Then, we use the estimated models to predict the flows for the test data set. We evaluate them with four metrics: the RMSE and the MAE, which are errors measured in commuters (the lower the better); \(R^2\), here the squared correlation between observed and predicted flows; and the Sørensen index (CPC) we used above. We use a function, because we will need these metrics more than once. Please note that the linear regression can predict negative flows, which we set to \(0\) for the CPC.

# A function which takes the observed and the predicted flows and calculates
# the metrics
ml_metrics <- function(obs, pred) {
  tibble(RMSE = sqrt(mean((obs - pred)^2)),
         MAE = mean(abs(obs - pred)),
         Rsquared = cor(obs, pred)^2,
         CPC = 2 * sum(pmin(obs, pmax(pred, 0))) / (sum(obs) + sum(pmax(pred, 0))))
}
